# CIP-186 deep-link signing in Yuti

Yuti is a wallet-side reference implementation of
[CIP-186](https://github.com/cardano-foundation/CIPs/tree/master/CIP-0186)
("Cardano Wallet Deep-Link Signing"). Builds with these patches accept
signing requests over `cip30dl-yuti://` and
`https://yuti.fluxpointstudios.com/cip30dl/v1/...`.

## Implemented

- URL receiver for iOS (`AppDelegate.application(_:open:options:)` plus
  `application(_:continue:restorationHandler:)`) and Android
  (`MainActivity.onNewIntent`).
- Strict ABNF parser (`lib/cip186/uri_parser.dart`) with critical-by-default
  unknown-key reject (-9), 12 KiB payload ceiling (-32), strict-unpadded
  base64url decoding for `dappKey`/`nonce`/`commit`/`payload`.
- Signing engine (`lib/cip186/signing_engine.dart`) that verifies
  `BLAKE2b-256(tx_body) == commit` and delegates to
  `CardanoWallet.signTransaction()` from `cardano_flutter_sdk`. The returned
  witness-set CBOR round-trips through `WitnessSet.deserializeBytes`.
- Attestation builder (`lib/cip186/attestation.dart`) constructs both
  approved and rejected callback URLs and the canonical-form subject the
  wallet Ed25519-signs: `cip30dl-v1\n` domain separator, lex-sorted
  query, uppercase-hex strict-unreserved percent encoding, `signature`
  appended as the final parameter.
- Orchestrator (`lib/cip186/deeplink_service.dart`) wired through
  `MethodChannel('com.yuti/cip30')`.

## Testing the deep-link flow

```bash
# iOS simulator
xcrun simctl openurl booted \
  'cip30dl-yuti:/v1/signTx?v=1&dappKey=AQE...&redirect=https%3A%2F%2Faegis.example%2Fcb&nonce=AgI...&commit=AAA...&ttl=1810000300&payload=cGF5'

# Android emulator
adb shell am start -a android.intent.action.VIEW \
  -d 'cip30dl-yuti:/v1/signTx?v=1&...' com.bluelight.bluelight

# Tests
flutter test test/cip186/
```

## Known limitations

- The orchestrator accepts a pluggable `SignTxPayloadDecoder` strategy.
  Production deployment must inject a NaCl-box decoder; the bundled
  `SignTxPayloadDecoder.plaintextJson` is the test-mode strategy.
- Session-binding Ed25519 vkey derivation (spec §Session-binding key
  derivation) is stubbed in the outgoing callback. The canonical-form
  bytes are computed by `AttestationBuilder.canonicalSubject` and ready
  for a real session-vkey to be injected.
- Hosting of the `.well-known/` claim files at
  `yuti.fluxpointstudios.com` is operational config; the entry-point
  code is wired but the JSON must be served by the wallet ops team.
- Methods other than `signTx` parse and emit `errorCode=-9` until their
  builders land (spec §Methods).
